Black Hole Screensaver - Milestone 4 Validated Configuration Schema
=====================================================================

Status: implementation and automated verification in progress. This is a
configuration and user-interface behavior milestone. Do not begin Milestone 5
until the verification and manual acceptance steps below have passed and the
user has explicitly approved the observed behavior.

This file is plain text because the repository ignores newly created Markdown
files.

1. Purpose
----------

Milestone 4 makes the existing registry-backed controls safe, versioned, and
predictable without changing the M3 renderer, its canonical GLSL source, or
screensaver lifecycle.

The compatible controls remain:

  HKCU\Software\BlackHoleScreensaver
    StarBrightness  DWORD  0..100  default 30
    DiskOpacity     DWORD  0..100  default 90
    Doppler         DWORD  0..100  default 60

The controls keep their existing labels, registry names, defaults, slider range,
and raw host normalization to 0.0..1.0 before SceneState uniform upload.

2. Schema and migration policy
------------------------------

The current schema marker is:

  ConfigSchemaVersion  DWORD  1

The following deliberately conservative policies apply:

- A key without ConfigSchemaVersion is a supported legacy configuration. Its
  individual compatible values are read when each is a correctly sized
  REG_DWORD in the 0..100 range.
- A missing, wrong-type, wrong-size, or out-of-range individual value falls
  back only to that field's compiled-in default. Valid sibling values remain.
- A present but invalid or unsupported schema marker makes the complete
  configuration fall back to compiled-in defaults. This avoids interpreting a
  future schema as if it were version 1.
- Reading configuration never repairs, creates, deletes, or rewrites registry
  values. Thus opening /c and choosing Cancel or closing the window never
  changes persisted data.
- Only an explicit /c OK writes values. It writes all three bounded DWORD
  controls and ConfigSchemaVersion, checks every operation, and closes only on
  full success. A write failure leaves the dialog open and reports the error.

This is a defensive configuration boundary. GLSL clamps remain defense in
depth, but no longer need to interpret unvalidated registry data in normal
operation.

3. Preserved runtime boundaries
-------------------------------

- Canonical GLSL and its generated C include are unchanged by this milestone.
- OpenGL 3.3, one full-screen glDrawArrays(GL_TRIANGLE_STRIP, 0, 4) pass, and
  N_STEPS = 48 remain required.
- No texture, sampler, FBO, desktop capture, image readback, post-processing,
  external runtime asset, or particle system is introduced.
- makeSceneState() still takes one host snapshot per rendered frame;
  uploadSceneState() remains the only scene-uniform upload seam.
- /s, /p, /d, /c, hidden first presentation, one-frame GPU fence, busy-frame
  skipping, and cooldown behavior remain unchanged.

4. Automated verification
-------------------------

From the project root:

  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\generate-shader-include.ps1 -Check
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\verify-milestone-4.ps1
  build.bat

After a successful build, the optional local runtime configuration probe may be
run. It temporarily replaces the current user's BlackHoleScreensaver registry
key with test fixtures, restores its exact prior state in finally, and must not
be run concurrently with a user editing settings:

  powershell.exe -STA -NoProfile -ExecutionPolicy Bypass -File .\tools\verify-milestone-4-runtime.ps1 -Executable .\blackhole.scr

The static verifier checks the canonical shader hash and generated include,
versioned configuration declarations and policies, bounded SceneState mapping,
centralized uniform upload, rendering constraints, and safe build promotion.
The runtime probe checks missing, legacy, current, malformed, and future
registry schemas plus explicit-OK persistence and Cancel/close no-write
behavior.

5. Manual acceptance (required stop gate)
------------------------------------------

1. With no registry key, open /c. The three sliders and labels must display
   30, 90, and 60. Cancel and window close must leave no new key behind.
2. With a legacy no-version key containing valid values, open /c and verify
   all values are retained. Cancel must not add ConfigSchemaVersion.
3. With one malformed setting, verify only that control falls back to its
   default while valid controls remain intact. Cancel must not repair the key.
4. With a future ConfigSchemaVersion, verify all three controls use their safe
   defaults and no automatic rewrite occurs.
5. Set distinct values, choose OK, reopen /c, and verify all values persist
   with ConfigSchemaVersion = 1.
6. Run /s, /p, and /d after valid and malformed configurations. Confirm the
   renderer opens, presents its prepared first frame, and produces no shader
   error log.
7. Confirm that Cancel, the title-bar close button, and a failed write do not
   report success or silently change a user's requested values.

Do not begin the quality, calibration, motion, Kerr, or binary milestones until
this behavior has been observed and explicitly approved.
